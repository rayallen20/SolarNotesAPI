# API 的 JSON 字段约定

## 大整数使用十进制字符串

新增或调整请求体、响应体时，凡是取值可能超出 JavaScript 安全整数范围（−9007199254740991 至 9007199254740991）的整数字段，一律使用 JSON 十进制字符串。按字段的允许范围确定类型，同一字段即使当前值为 1，也写作 `"1"`。这条约定同样适用于嵌套对象的关联 ID 和 ID 数组中的每一项。

例如，天体列表中的一条记录含有 `"id":"9007199254740993"`，书单请求原样传回 `{"planet":{"id":"9007199254740993"}}`。

- **后端**在 JSON 边界进行转换。对于正 `int64` 的天体、书籍、目录节点和文章 ID，响应通过 `strconv.FormatInt(id, 10)` 输出，请求通过 `json:"id,string"` 和 `binding:"gt=0"` 绑定并校验。其他字段按其实际取值范围校验。
- **前端**以 `string` 接收、保存和回传，在组件、状态、路由和 API 调用之间始终保留原始文本。经过 `Number()` 或 `parseInt()` 的大 ID 可能已经舍入，再转回字符串也无法恢复。
- **接口联调**同步更新字段表、JSON 示例及两端类型声明，使用 `"9007199254740993"` 之类的值验证从响应到下次请求逐位一致。

## 现有接口的衔接

天体简介响应中的 `data.planets[].id` 和书单请求中的 `planet.id` 已按此约定传输。[天体简介 API](天体简介API.md) · [获取书籍列表 API](获取书籍列表API.md)

书单响应中的 `data.bookList[].id` 以十进制字符串传输。读取目录时，前端将书籍 ID 原样传回，例如 `{"book":{"id":"9007199254740995"}}`。[获取书籍列表 API](获取书籍列表API.md) · [获取目录 API](获取目录API.md)

目录树各层节点的 `id` 均为十进制字符串。前端点选公开文件时原样传回目录节点 ID，例如 `{"catalogue":{"id":"2123684178049376261"}}`。响应中的 `data.article.id` 是关联文章自身的主键，本例为 `"2123684178049376262"`。同一响应包含该文章的 Markdown 正文和创建日期。[获取目录 API](获取目录API.md) · [获取文章 API](获取文章API.md)
