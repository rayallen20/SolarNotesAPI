GET /api/v1/planet/list

天体简介 API 实现方案

前台通过这一次请求，把数据库中的标题、简介和主键交给太阳系场景。控制器通过业务层和 DAO 读取 solar_notes.planet。天体主键在 JSON 中使用十进制字符串，前端聚焦天体时将它原样传给书单接口。

审阅完整 Go 代码 · 前台接口契约 · 天体控制器 · 启动与数据库连接

请求与成功响应

前端发送公开 GET 请求，无需鉴权、查询参数或请求体。成功时返回 HTTP 200，前端检查数字 code === 200 后从 data 解包 planets 数组。以下示例假设库中只有一条天体记录。

{
  "code": 200,
  "message": "success",
  "data": {
    "planets": [
      {"id": "9007199254740993", "name": "Sun", "title": "操作系统", "intro": "操作系统相关介绍"}
    ]
  }
}

每项四个字段均取自同一行。id 是正 int64 主键的十进制字符串。前端用区分大小写的 name 匹配场景天体，并将 title 和 intro 用于标签和面板。即使标题或简介为空，响应也保留相应字段。

查询范围与展示顺序

SELECT id, name, title, intro
FROM planet
ORDER BY id ASC;

原接口给出了九项示例，未约定返回数量或顺序。本方案沿用管理后台列表的规则，返回所有已建天体，包括尚未关联书籍的天体。DAO 先按主键升序读取，业务层再按以下规则组织结果。

  1. 已建的标准名称按 Sun → Mercury → Venus → Earth → Mars → Jupiter → Saturn → Uranus → Neptune 排列。缺少某个天体时直接跳过，所有返回的 ID 均来自实际记录。
  2. 数据库中若有其他名称，附在标准天体之后，保持主键升序。前端只给名称完全匹配的场景对象赋值。
  3. 空表属于查询成功，返回 {"code":200,"message":"success","data":{"planets":[]}}。

真实主键与书单联调

后台创建天体时生成 64 位雪花 ID。天体列表控制器用 strconv.FormatInt(planet.ID, 10) 输出其十进制文本。场景将这个字符串保存到 userData.id，用户聚焦天体时，前端直接用它构造 POST /api/v1/book/list 的请求体。

{"planet":{"id":"9007199254740993"}}

书单入参用 json:"id,string" 将带引号的十进制值精确解码为 int64，再用 gt=0 校验。发送 JSON 数字、零、负数或超出 9223372036854775807 的值均返回参数校验码 10101。书单响应的 bookList[].id 表示书籍主键，其 JSON 类型为整数。

失败响应

前台接口文档只定义了成功响应。当前前台响应包已有成功码和参数校验码，此处建议新增后台已有的两类错误映射，继续使用 HTTP 200，由业务码驱动前端的失败分支。

情形业务码公开消息与载荷
请求期间查询数据库失败10201“数据库操作失败,请稍后重试”，data: {}
其他内部处理错误500“服务暂时不可用,请稍后重试”，data: {}

公开消息使用固定文本，SQL、连接细节和底层错误留在服务端。若数据库在进程启动时就无法连接，服务会在监听前退出，此时没有 HTTP 响应。

controller/v1/planet/planet.go

传入请求上下文，识别数据库错误，将业务实体映射为公开字段。主键在这里格式化为十进制文本，空结果编码为数组。

package planet

import (
	"errors"
	"net/http"
	"strconv"

	"SolarNotesAPI/biz"
	respPlanet "SolarNotesAPI/param/resp/v1/planet"
	"SolarNotesAPI/resp_body"
	"SolarNotesAPI/sys_error"

	"github.com/gin-gonic/gin"
)

// List 返回太阳系场景所需的天体简介。
func List(c *gin.Context) {
	var body resp_body.RespBody
	var service biz.Planet
	planets, err := service.List(c.Request.Context())
	if err != nil {
		var dbErr *sys_error.DatabaseError
		if errors.As(err, &dbErr) {
			body.DBError()
		} else {
			body.InternalError()
		}
		c.JSON(http.StatusOK, body)
		return
	}

	list := respPlanet.ListResp{
		Planets: make([]respPlanet.ListPlanetResp, 0, len(planets)),
	}
	for _, planet := range planets {
		list.Planets = append(list.Planets, respPlanet.ListPlanetResp{
			ID:    strconv.FormatInt(planet.ID, 10),
			Name:  planet.Name,
			Title: planet.Title,
			Intro: planet.Intro,
		})
	}
	body.Success(map[string]any{"planets": list.Planets})
	c.JSON(http.StatusOK, body)
}

biz/planet.go

查询结果按标准名称的顺序稳定排序。所有未知名称使用相同排序值，因此保留查询时的主键顺序。

package biz

import (
	"cmp"
	"context"
	"errors"
	"slices"

	"SolarNotesAPI/model"
	"SolarNotesAPI/sys_error"
)

type Planet struct {
	ID    int64
	Name  string
	Title string
	Intro string
}

var planetDisplayOrder = []string{
	"Sun", "Mercury", "Venus", "Earth", "Mars",
	"Jupiter", "Saturn", "Uranus", "Neptune",
}

func planetRank(name string) int {
	if index := slices.Index(planetDisplayOrder, name); index >= 0 {
		return index
	}
	return len(planetDisplayOrder)
}

// List 将已创建的天体按前台展示顺序返回。
func (Planet) List(ctx context.Context) ([]Planet, error) {
	if ctx == nil {
		return nil, &sys_error.InternalError{Cause: errors.New("biz.Planet.List 缺少请求上下文")}
	}

	var dao model.Planet
	rows, err := dao.FindAll(ctx)
	if err != nil {
		return nil, &sys_error.DatabaseError{Cause: err}
	}

	planets := make([]Planet, 0, len(rows))
	for _, row := range rows {
		planets = append(planets, Planet{
			ID:    row.ID,
			Name:  row.Name,
			Title: row.Title,
			Intro: row.Intro,
		})
	}

	// 未知名称的排序值相同。稳定排序会保留 DAO 提供的主键顺序。
	slices.SortStableFunc(planets, func(a, b Planet) int {
		return cmp.Compare(planetRank(a.Name), planetRank(b.Name))
	})
	return planets, nil
}

model/planet.go

GORM 从目标切片的元素类型推导表名，沿用启动时设置的单数表命名策略。查询只选择响应需要的四列。

package model

import (
	"context"
	"errors"

	"SolarNotesAPI/db"
)

// Planet 映射 planet 表中简介接口需要的列。
type Planet struct {
	ID    int64  `gorm:"column:id;primaryKey;autoIncrement:false"`
	Name  string `gorm:"column:name"`
	Title string `gorm:"column:title"`
	Intro string `gorm:"column:intro"`
}

// FindAll 按主键升序读取所有已创建的天体。
func (Planet) FindAll(ctx context.Context) ([]Planet, error) {
	if db.DB == nil {
		return nil, errors.New("数据库连接尚未初始化")
	}

	var rows []Planet
	err := db.DB.WithContext(ctx).
		Select("id", "name", "title", "intro").
		Order("id ASC").
		Find(&rows).Error
	if err != nil {
		return nil, err
	}
	return rows, nil
}

resp_body/resp_body.go

在原文件中增加两个业务码和对应的响应方法。Success 和 ValidateFailed 仍可供已有控制器调用。

package resp_body

import "SolarNotesAPI/sys_error"

// RespBody 本结构体用于定义响应体结构
type RespBody struct {
	Code    int                    `json:"code"`    // Code 响应体中的状态码部分
	Message string                 `json:"message"` // Message 响应体中的消息部分
	Data    map[string]interface{} `json:"data"`    // Data 响应体中的数据载荷部分
}

// 响应码规则:
// 200: 成功响应
// 10XXX: 系统级别错误
// 101XX: 参数校验错误
const (
	ServiceInternalErrorCode = 500
	DBErrorCode              = 10201
	SUCCESS                  = 200   // SUCCESS 成功响应
	ValidateFailed           = 10101 // ValidateFailed 参数校验失败
)

// Success 本方法用于定义成功响应时的响应体
func (r *RespBody) Success(data map[string]interface{}) {
	r.Code = SUCCESS
	r.Message = "success"
	r.Data = data
}

// ValidateFailed 本方法用于定义参数校验失败时的响应体
func (r *RespBody) ValidateFailed(err error) {
	r.Code = ValidateFailed
	r.Message = err.Error()
	r.Data = map[string]interface{}{}
}

// DBError 和 InternalError 仅输出公开消息。
func (r *RespBody) DBError() {
	r.failure(DBErrorCode, sys_error.DatabaseMessage)
}

func (r *RespBody) InternalError() {
	r.failure(ServiceInternalErrorCode, sys_error.InternalMessage)
}

func (r *RespBody) failure(code int, message string) {
	r.Code = code
	r.Message = message
	r.Data = map[string]any{}
}

实施后的验收

实库联调中，solar_notes.planet 返回的 9 个主键均超过 JavaScript 安全整数上限。用 JavaScript 解析天体响应并生成书单请求后，9 个字符串均与 SQL 查询的主键逐位相同，9 次书单请求全部成功。裸数字及超出正 int64 范围的字符串都返回了 10101。

curl -sS -i http://127.0.0.1:4061/api/v1/planet/list
场景检查项
真实数据在测试库中准备一个与 mock 不同的标题，且该天体没有关联书籍。调用接口，核对真实主键、名称、标题及简介，确认 HTTP 200、数字业务码 200 和四个字段的 JSON 类型。
部分天体与顺序用打乱主键顺序的 Earth、Sun 和两条非标准名称记录，预期先得到 Sun、Earth，再得到按 ID 升序的两条记录，总数为四。
空表与查询故障用空数据集验证成功码和空数组。模拟 DAO 查询失败时，核对业务码 10201、空对象及固定公开消息。
书单联调使用大于 JavaScript 安全整数上限的真实主键，对照数据库十进制原文、列表响应中的字符串及书单请求里的 planet.id，三处须逐位一致。字符串请求应成功，把该字段改为 JSON 数字重发，应收到 10101。
